## Only after explicit publication authorization

1. Use a clean checkout of the verified main release commit. Recheck npm identity/permissions, the official Registry and that 0.1.1 is still absent. Run `npm publish --access public --registry=https://registry.npmjs.org/` once; the owner completes any browser/Windows Hello/2FA prompt directly. On failure, inspect Registry state and the cause before deciding what to do; never blindly retry or create a 2FA-bypass token.
2. Verify official version metadata and `latest`, then run `npm run test:consumer -- --registry` from the release checkout. This installs the exact official version in fresh projects and compares integrity, JS/types/CSS, bilingual docs and complete licenses to release source; it checks `gitHead` if provided and explicitly reports its absence otherwise. Do not claim success from a local tarball alone.
3. After npm and Registry checks succeed, create and push annotated `v0.1.1` pointing to the actual published main source. Create the concise GitHub Release from [release notes](v0.1.1-release-notes.md), then verify npm/README/Release/CI and report completion in Issue #13.
