## Distribution and selectors

One package, unchanged core and unique React Hook, unchanged `styles.css`, plus **one optional CSS export**:

```ts
import "@librecosta/liquid-glass/styles.css";    // base refraction rules
import "@librecosta/liquid-glass/materials.css"; // optional presentation only
```

`src/materials.css` is copied verbatim to `dist/materials.css`. Playground and the development prototype import that same source. The old prototype CSS path contains only a forwarding import, preserving historical document links without duplicating rules. No material JavaScript, manager, component, context, dependency or automatic theme/background sampling is added.

| Opt-in contract | Behavior |
| --- | --- |
| `.liquid-glass[data-lg-material="clear"]` | Original Playground white tint, no added pseudo decoration |
| `.liquid-glass[data-lg-material="soft"]` | Approved Clearer: 7% tint; 6% when this host explicitly has `data-lg-theme="light"` |
| `.liquid-glass[data-lg-material="prismatic"]` | Reviewed neutral background gradient; no optical parameter changes |
| `data-lg-theme="light\|dark"` on each host | Application-selected theme; missing/unknown values use dark tint. Ancestor/system theme is not inferred |
| `data-lg-decorate` on Soft/Prismatic | Explicitly reserves an unused `::after` for the reviewed shadow/gloss; attribute presence enables it |

Both the class and known material value are required. Omitted/unknown material leaves the host unskinned. Theme only changes Soft's tint/shadow; Clear and Prismatic keep their reviewed appearance in both themes. Host selectors have specificity **0-1-0**; pseudo selectors have **0-1-1**. Ordinary application classes loaded later can override host backgrounds. No `!important` or global theme selectors.

Complete executable native div/button/input examples and imports are in [English](../README.md#optional-materials) and [中文](../README.zh-CN.md#可选材质). React uses the same attributes on the caller's elements alongside the existing `useLiquidGlass` ref. Quality remains controlled by `QUALITY_PRESETS` / local options, independently of Material; Prismatic's recommended optics remain an explicit Playground-only experiment.

```html
<button class="liquid-glass own-button" type="button"
  data-lg-material="soft" data-lg-theme="light" data-lg-decorate>Save</button>
<style>
  .own-button { position: relative; padding: 12px 20px; border: 0; border-radius: 20px; font: inherit; color: inherit; }
  .own-button:focus-visible { outline: 2px solid currentColor; outline-offset: 3px; }
</style>
```

Bind the existing core/Hook as in the README. The stylesheet alone adds presentation; it does not create an engine instance.

## Ownership and composition limits

- The application owns size, radius, static/relative/absolute/fixed positioning, fonts, text contrast, focus, disabled state, native events, stacking and clipping. The stylesheet sets **no host layout or positioning**. Application button states can override a skin deliberately; Playground retains its reviewed native button states, including daylight Soft's 6% hover tint.
- Decoration requires a containing block supplied by the host, usually existing relative/absolute/fixed positioning. `::after` is absolute, `inset:0`, inherits radius and has `pointer-events:none`. No clipping or extra wrapper is imposed.
- **Existing `::after` is not taken over by default.** Leave off `data-lg-decorate` when the application owns it; tint/gradient still applies. Full reviewed decoration and arbitrary application content in the same pseudo-element cannot be combined automatically. Choose an existing independent decorative surface when needed; no prefab Card wrapper is introduced.
- Replaced native inputs must not rely on pseudo-element support. Bind a separate `aria-hidden`, `pointer-events:none` surface under a transparent native input. Keep labels, caret, text selection, form values and focus on the real input. See the tested README example and prototype.
- Material CSS never writes `backdrop-filter`, `filter`, `--hyalite`, `--hyalite-edge` or maps. Existing base CSS/engine retain SVG and blur fallback ownership. Skins do not promise text contrast on arbitrary images or universal Safari/Firefox/assistive-technology coverage.

## Performance and release status

M3 introduces no optical/performance changes and makes no new speed claim. The [M2 measurements](m2-material-contract.md) retain 54 actual trials: 20-card Clear rAF p95 medians were Balanced **229.2ms**, Fast **133.3ms**; material switches added no maps/PNGs and retained filter/DOM identity. These are callback intervals, **not painted FPS**. Twenty overlapping surfaces remain expensive; measure the actual target device.
