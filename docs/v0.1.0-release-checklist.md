# v0.1.0 release checklist

First public release of `@librecosta/liquid-glass@0.1.0`, following [Issue #6](https://github.com/librecosta/liquid-glass/issues/6) and the owner's explicit publication authorization. The RC baseline is `bd0f44d`; the owner's existing removal of `private` is retained. Package and lockfile stay at `0.1.0`, with `publishConfig.access: public`.

## Confirmed prerequisites

- [x] npm identity `gofurry`; `npm org ls librecosta` reports Owner. Account email is verified and 2FA is `auth-and-writes` (checked 2026-11-05). No bypass token is created.
- [x] The owner explicitly authorized the normal dev→main PR merge, first public npm publication, annotated tag, GitHub Release and completion of the release issue. No further per-step approval is required; interactive security verification remains with the owner.
- [x] ESM core, sole React Hook and optional CSS exports are unchanged. Balanced defaults, explicit Fast switching and historical Reference remain protected.
- [x] Core has no runtime dependencies. React 19 is optional for the core and required by `/react`; consumers supply React DOM. Node 24 is a source-tooling requirement, not a claimed browser runtime minimum.
- [x] English/Chinese README, changelog and Release text use the public version and Registry installation command. Historical RC reports remain historical records.

## Verification and publication sequence

1. Run `npm ci`, `npm run check` and `npm pack --dry-run` on the release changes. Check exact exports/types, both README examples, independent core-only and React consumers, SSR/StrictMode, native interactions, quality switching, lifecycle cleanup, licenses and package allowlist. No images, demos, tests, Playwright resources or bundled React enter the package.
2. Push dev, open a normal PR to main, require successful CI and merge without force pushing. Verify the resulting main commit's CI. Existing Ubuntu CI skips only the two Windows-specific screenshot tests; exact Node math and portable map/SVG contracts still run. Compatible Windows Chrome checks retain the original zero-tolerance Reference/C3 pixel goldens.
3. Publish from a clean checkout of that verified main commit using `npm publish --access public --registry=https://registry.npmjs.org/`. Complete any browser/Windows Hello/2FA prompt directly; never copy credentials or OTP into repository records. If publication fails, inspect the failure and Registry state rather than looping retries.
4. On the same main commit run `npm run test:consumer -- --registry`. This fetches the exact official version, checks its Registry integrity and `gitHead` when supplied, installs it by Registry version in fresh core-only and React projects, checks package metadata, documentation, compiled runtime/type/CSS and licenses against release source, compiles all bilingual examples, and runs SSR plus development StrictMode/production browser behavior. Missing optional `gitHead` is reported explicitly, never inferred. Report: `test-results/registry.json`.
5. Only after publication and Registry verification succeed, create and push annotated `v0.1.0` pointing to the published main commit, then create the GitHub Release from [Release notes](v0.1.0-release-notes.md). Check npm/main README/Release/CI and close the completed release issue with the actual evidence.

## Remaining photo and hosting restriction

Forest original-source rights remain unverified. The owner-supplied CC0 statement is recorded in [provenance](../src/assets/forest.provenance.json); source repository MIT is not evidence for the photograph. Photo/screenshot binaries are excluded from npm. **Do not enable or deploy public GitHub Pages.** Obtain original license evidence or approve a verified replacement before public demo hosting.

Real Safari/Firefox, physical touch devices and assistive-technology combinations still need broader coverage; v0.1.0 is not a claim of universal browser compatibility.
